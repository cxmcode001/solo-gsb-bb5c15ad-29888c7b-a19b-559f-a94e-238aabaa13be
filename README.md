# Unicode 字体回退链审计台

无需登录的纯前端审计工具（React + TypeScript + Vite）：粘贴待渲染文本、录入字体名称及其
Unicode 覆盖范围，系统按**字素簇**（grapheme cluster）计算每种字体可覆盖的字符并标出缺失项；
核心求解器在**保持字体顺序偏好**与**链长度最短**之间折中，求出可行回退链，解释每个字素簇由
哪种字体承接，并导出 **CSS font-family** 与**审计 JSON**。

支持两种模式（左上角切换，文本互不丢失）：

- **单场景**：一段文本，独立求解（与历史版本完全一致）；
- **场景集**：维护最多 **20 个**命名文本场景（新增 / 重命名 / 删除），所有场景的字素簇
  **合并参与一次回退链求解**，链中字体及顺序**全局唯一**；结果按场景分别展示覆盖率、
  缺失簇与承接字体。跨场景重复文本**分别计数**、绝不合并；空场景保留但不参与求解。
  修改任一场景文本或任一字体后，共享链与全部场景结果同步重算。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**

- 端口映射：宿主机 `8080` → 容器 `80`（在 `docker-compose.yml` 的 `ports` 中可改）
- 后台运行：`docker compose up -d --build`
- 停止：`docker compose down`

也可以只用 Docker：

```bash
docker build -t font-fallback-audit .
docker run --rm -p 8080:80 font-fallback-audit
# 访问 http://localhost:8080
```

## 本地开发

npm install
npm run dev        # 开发服务器 http://localhost:5173

## 使用说明

1. **待渲染文本（单场景 / 场景集）**：左上角切换模式。
   - 单场景模式下若已有多个场景，可在下拉框中选择本次审计对象（其余场景文本保留、
     不参与求解）。
   - 场景集模式下通过场景清单**新增 / 重命名 / 删除**场景（上限 20 个，至少保留 1 个），
     点击任一场景即可编辑其文本。系统用 `Intl.Segmenter` 切分为字素簇（正确处理
     ZWJ 表情序列、组合符、旗帜等）。清单上实时显示每个场景的簇数，空场景会保留但
     不贡献需求模式；全部场景簇**合并做一次求解**，相同文本出现在多个场景时
     **分别计数、不会跨场景合并**。「载入示例场景集」可一键填入示例。
2. **字体与覆盖范围**：逐行录入字体名称与 Unicode 范围，**列表顺序即回退偏好**
   （可用 ↑↓ 调整）。范围语法：
   - `U+0020-007E`（区间）、`U+4E00`（单码位）、`U+4??`（通配，等价 `U+400-4FF`）
   - 多个范围用逗号、分号或空白分隔；`U+` 前缀可省略
   - 每个条目还可**上传本地 TTF/OTF**：浏览器端直接解析 sfnt 的 `cmap`
     （format 4 与 12）得到字体**实际**映射的码位区间（映射到非 0 glyph id），
     并显示声明范围与实测覆盖的**双向差集**（声明有·实测无 / 实测有·声明无，
     含码位数与紧凑区间）。文件仅在本机内存中解析，**不发送服务端、不写入任何
     浏览器存储**；清除文件后立即丢弃。表偏移/长度/分段非法时只在该条目内报错，
     不影响声明范围，也不影响其他字体（不支持 `.ttc` 集合）。
3. **求解偏好**：滑杆在「顺序优先」与「链长优先」之间调节权重；可勾选是否忽略
   透明格式字符（ZWJ、变体选择符等，默认忽略，随簇内其它字符渲染）。
   勾选 **「按实测覆盖求解」**（至少上传一个字体后可用）后：
   - 已上传且解析成功的字体，以 cmap **实测**码位参与字素簇分析、回退链求解与审计 JSON；
   - 未上传（或已清除）文件的字体仍使用**声明范围**；
   - 关闭开关或清除文件立即恢复声明范围。
4. **结果**：
   - **单场景模式**：概览统计、最优回退链（每种字体承接多少簇）、缺失告警、逐字素簇明细
     （可筛选），以及一键复制/下载的 CSS 与审计 JSON。审计 JSON 中每个字体含
     `effectiveCoverage`（本次实际生效的来源与区间）与 `declaredVsMeasured`（双向差集）。
   - **场景集模式**：顶部为全部场景合计统计与**共享回退链**（链中字体全局唯一，
     每种字体显示跨场景合计承接簇数与逐场景分布矩阵）；「逐场景结果」标签页分别给出
     每个场景的**覆盖率**、缺失告警、**本场景承接字体**、基线对比与逐字素簇明细
     （簇编号为场景内序号）。修改任一场景文本或任一字体范围/顺序后，合并求解与
     全部场景明细同步重算。导出的 CSS 使用共享链；场景集审计 JSON 含场景清单、
     共享链（`sharedChain` + `perScenario`）与逐场景明细（`result.scenarios[*]`）。
5. **单字体失效韧性分析**：对当前最优回退链中的每种字体，逐一模拟其不可用，并在
   **保持原始偏好顺序与当前声明/实测覆盖模式**的前提下重新求解回退链。场景集模式下
   重解同样合并全部场景，新增缺失/改接明细会标注所属场景。风险卡片按
   **新增缺失数**降序展示：失效后的新增缺失簇、改由其他字体承接的簇、替代回退链
   及链长变化（求解在过滤后的临时下标空间进行，结果始终映射回原始字体条目，名称
   不会错配）。可一键下载韧性分析 JSON（`font-fallback-resilience.json`）。
6. **补字预算规划**：在结果区的「补字预算规划」面板输入最多可新增的不同
   **（字体, 码位）对**数（预算），系统仅针对**当前缺失的非自由字素簇**预演补字：
   - 簇内全部必需码位须由**同一有效字体**的已有覆盖（随当前声明/实测模式）或
     新增补丁覆盖，该簇才算恢复，不允许一个簇拆给多个字体；
   - 同一（字体, 码位）对跨簇复用**只计一次**，不同字体**分别计费**；
   - 每轮枚举「缺失簇 × 有效字体」的最小补丁，按
     **新增恢复簇数 / 新增对数**贪心选择，平局依次取较少新增对数、较前字体
     （偏好位次）、较前场景/簇；只选择预算内方案，并在**每轮后重新计算恢复数**
     （补丁复用会使后续代价下降）；
   - 面板显示**逐场景预计恢复/仍缺失簇数**、预算用量、**全恢复所需最少对数**、
     逐轮明细，以及**按字体归组的补码清单**（紧凑区间 + 全部码位可展开）；
   - 点击「下载方案 JSON」导出 `font-fallback-budget-plan.json`（含汇总、逐场景、
     逐轮、按字体补码、恢复/仍缺失簇完整清单）；
   - 文本、字体、声明/实测覆盖模式或预算变化时方案**同步重算**；规划仅为预演，
     **不修改**原求解结果与字体范围。当前没有缺失簇时面板提示无需补字。
7. **基线对比**：在结果区点击「导入审计 JSON」，选择本工具此前通过「下载 .json」
   导出的审计结果，即可与**当前实时结果**对比（场景集模式下为当前选中场景的簇序列；
   导入场景集导出的 JSON 时按其场景顺序展平）：
   - 按**字素簇文本序列**做保序对齐（LCS）：重复簇按出现次序**逐次匹配**，
     不会跨序错配；插入/删除的簇**只标记自身一行**，后续簇仍以各自序列中的真实
     序号显示，不会整体错位。
   - 已对齐簇区分**覆盖状态变化**（新增缺失 / 已修复缺失、自由簇状态变化）与
     **承接字体变化**（字体改接），并汇总：新增缺失、已修复缺失、字体改接、
     插入/删除簇数与实时缺失总数。
   - 勾选「**仅看退化项**」只保留新增缺失的对齐簇与新插入的缺失簇。
   - 「下载对比 JSON」（`font-fallback-baseline-comparison.json`）含汇总统计与
     **完整对齐明细**（每行的基线/实时 index、文本、码位、状态、承接字体及变化类别，
     超长表格只在界面截断、JSON 不截断）。
   - 非法 JSON、`tool`/`version` 不匹配或缺少簇数据时**只在面板内报错**，
     并保留上一次有效基线。点击「移除基线」可退出对比。

### 审计 JSON 兼容性

- **单文本导出保持原可导入基线**：单场景模式导出的 JSON 结构与历史版本一致
  （`input.text` + `result.chain`/`result.clusters`，仅新增不影响解析的 `mode: "single"` 字段），
  老版本导出的 JSON（无 `mode` 字段）也仍可导入。
- **场景集导出**：`mode: "scenario-set"`，含 `input.scenarios`（场景清单）、
  `result.sharedChain`（共享链与逐场景承接数）、`result.scenarios[*]`
  （每场景覆盖率、缺失簇、承接字体、局部/全局双下标簇明细）。该形态同样可被基线导入器
  读取（按场景顺序展平所有簇）。

## 求解模型

- 每个字素簇要求：簇内全部「需覆盖码位」都落在某字体范围内，该字体才可承接此簇。
- 场景集模式把**所有场景**的簇合并后再抽取需求模式：候选字体集合相同的簇
  （即使文本相同且出现在不同场景）共享同一条模式约束，因此一次求解即可得到
  **全局唯一**的回退链；但承接簇数、覆盖率、缺失明细始终**按簇分别统计**，
  跨场景重复文本不会合并计数。
- 求解目标：为所有可覆盖的簇选出字体子集（hitting set），最小化
  `λ·链长 + (1-λ)·偏好位次代价`，λ 由滑杆控制；选出的字体按偏好顺序排列即为
  CSS font-family 回退顺序，每个簇由链中第一种可覆盖字体承接（与浏览器回退语义一致）。
- 算法：无可覆盖字体的簇直接标记**缺失** → 唯一候选字体强制入选 → 支配约简 →
  贪心 + 删除/交换局部搜索得到初始解 → **分支定界**在节点预算内求精确最优
  （超预算或规模过大时自动退回启发式解，并在界面标注「启发式」）。

## 目录结构

```
├── Dockerfile             # 多阶段：node 构建 → nginx 托管
├── docker-compose.yml     # 一键启动，端口 8080:80
├── nginx.conf             # SPA 回退 + 静态资源缓存
├── index.html
└── src/
    ├── App.tsx            # 状态编排：模式/场景/文本/字体 → 合并分析 → 求解 → 展示
    ├── lib/
    │   ├── grapheme.ts    # 字素簇切分（Intl.Segmenter）、透明码位
    │   ├── scenarios.ts   # 文本场景（新增/命名/上限 20）与示例场景集
    │   ├── ranges.ts      # Unicode 范围解析（含 U+4?? 通配）、区间差集
    │   ├── sfnt.ts        # 浏览器端 sfnt cmap（format 4/12）解析
    │   ├── coverage.ts    # 多场景合并逐簇覆盖分析（模式跨场景去重、簇不去重）
    │   ├── solver.ts      # 回退链求解（分支定界 + 启发式兜底）
    │   ├── resilience.ts  # 单字体失效韧性分析（多场景重解，映射回原下标）
    │   ├── patching.ts    # 补字预算规划（缺失簇×字体最小补丁，按恢复/代价贪心）
    │   ├── baseline.ts    # 审计 JSON 解析（兼容单文本/场景集）+ 保序对齐 + 对比报告
    │   └── audit.ts       # CSS / 单文本 / 场景集 / 韧性分析 JSON 导出
    └── components/        # 场景编辑器、字体编辑器、明细表、单文本/场景集结果面板、
                           # 韧性分析面板、补字预算规划面板、基线对比面板
```

## 隐私

整个应用为纯静态站点，无后端接口。上传的 `.ttf/.otf` 通过
[`File.arrayBuffer()`](https://developer.mozilla.org/docs/Web/API/Blob/arrayBuffer)
读入当前页面内存，仅解析 cmap 得到码位区间后即可被垃圾回收；**不会**发起网络上传、
不会写入 `localStorage`/IndexedDB/cookie，刷新页面即消失。
